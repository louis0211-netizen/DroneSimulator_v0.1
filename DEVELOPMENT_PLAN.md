# DEVELOPMENT_PLAN

## Phase 1: Flight Physics Core

Goal: A quadcopter can arm, take off, hover, move, yaw, land, crash, and reset using Rigidbody-based physics.

Implemented first:

- `DronePhysics`
- `MotorMixer`
- `FlightController`
- `DroneInputManager`
- Shared flight data types
- Fallback compile-check harness

Validation:

- Compile scripts in Unity 6.
- Verify Rigidbody movement in Play Mode.
- Tune hover throttle and motor response before adding richer features.

Status:

- Runtime fallback C# compile check passed.
- Editor fallback C# compile check passed.
- Unity Hub and Unity Editor `6000.3.23f1` were installed.
- Unity batchmode compile/import passed after Unity login/license activation.
- MVP scene was generated by Unity batchmode.
- On this Windows machine, Unity CLI did not expose an installable `ios` module.

## Phase 2: Control Feel

- Add PID profiles for Stabilized mode.
- Add rate tuning for Acro mode.
- Add expo curves and dead zones for virtual sticks.
- Add preset-driven mass, arm length, drag, and motor values.

Status:

- First PID/rate profile is implemented in `DronePreset`.
- Stabilized mode uses angle-to-rate control, then rate PID to motor mixer demand.
- Acro mode uses rate PID directly.
- Mixer authority and armed idle output are preset-driven.
- Stick dead zone, stick expo, and throttle expo are preset-driven.

## Phase 3: iOS Input

- Build landscape UI canvas.

Status:
